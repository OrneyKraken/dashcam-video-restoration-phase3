# Qualitative results — before/after visual material

Generated by `scripts/make_qualitative.py` via `scripts/run_qualitative.bat`.

## Clip selection — deliberately not cherry-picked

Three clips, one per lighting condition, each the **median** clip for that condition by
DashMamba-minus-RVRT PSNR on `gaussian/high`. One of them is a clip DashMamba **loses**.

| Clip | Lighting | DashMamba | RVRT | FastDVDnet | BasicVSR++ | Note |
|---|---|---|---|---|---|---|
| `raw_video_013_clip_0009` | night | **31.68** | 28.22 | 28.43 | 16.54 | median night clip |
| `raw_video_022_clip_0018` | evening | **29.82** | 27.21 | 27.34 | 16.80 | median evening clip |
| `raw_video_021_clip_0024` | day | 29.31 | **30.43** | 29.65 | 16.04 | **DashMamba loses** — median day clip |

(PSNR over the 40 rendered frames, so these differ slightly from the 80-frame benchmark
means in `RESULTS_AND_DIAGNOSIS.md`.)

Presenting a grid of wins only is the fastest way to invite the question "which clips did
you leave out?" in a defence. The day clip is included precisely because it loses.

## What was produced

For each of the three clips, under
`results/qualitative/<clip>_gaussian_high/` on the training machine (F: drive):

| File | Contents |
|---|---|
| `frame_0000_1_clean_ground_truth.png`, `frame_0020_*` | ground truth |
| `frame_XXXX_2_noisy_input.png` | the degraded input — the "before" |
| `frame_XXXX_3_<model>.png` | each of the four models' restoration — the "after" |
| `compare_frame_XXXX.png` | all six panels side by side, labelled (~11 MB each) |
| `crops_frame_XXXX.png` | 2× zoomed centre detail crop, same layout (~2 MB) |
| `video_<model>.mp4` | 40-frame split-screen BEFORE \| AFTER clip, 15 fps (~21 MB each) |

Total 382 MB. **Only the `crops_*.png` files are committed to git** (see
`figures/`); the full-resolution grids and the MP4s stay on the training machine because
they are too large to version sensibly. Regenerate any of them with one command — see
below.

The degradation applied here uses the identical seeded `p3_degrade` path as
`p3_evaluate.py`, so the "before" frame is bit-identical to what was actually scored.

## What the visuals show

1. **BasicVSR++ barely denoises at all.** Its output is visibly still noisy in every
   clip. This is a checkpoint domain mismatch — it was trained for compressed-video
   artifact removal, not sensor noise — and the images make the 16 dB numbers legible
   at a glance.
2. **RVRT and FastDVDnet desaturate.** They remove chroma noise by removing chroma,
   and brighten the frame by roughly +0.02. Clean-looking but colour-shifted.
3. **DashMamba holds colour far more faithfully but leaves chroma noise.** Mean colour
   error is ~0.002 against 0.008–0.026 for the baselines, yet its output runs
   1.18–2.18× oversaturated because residual colour blotches survive.

Point 3 is the visual explanation for the PSNR/SSIM divergence at σ50 — see
`RESULTS_AND_DIAGNOSIS.md` §1, "Chroma behaviour".

## Regenerating

```bat
REM From the repo's scripts/ directory on a machine with the dataset present.
REM The .bat wrapper is REQUIRED for RVRT: it JIT-compiles a CUDA extension and
REM needs MSVC + CUDA 12.4 + ninja on PATH, and it redirects the build off the
REM C: drive (which was full on the training machine).
run_qualitative.bat --clips raw_video_013_clip_0009 raw_video_022_clip_0018 raw_video_021_clip_0024 ^
    --kind gaussian --level high --frames 40 --save-frames 0 20
```

Other axes work the same way, e.g. `--kind poisson_gaussian --level realistic`.

### Two traps this script had to work around

- **Vendored repos collide on the module name `models`.** RVRT ships a `models/`
  package; FastDVDnet ships a `models.py`. Whichever imports first makes the other
  fail with `'models' is not a package`. The metric runs never hit this because each
  run imported exactly one model. `make_qualitative.py` therefore re-invokes itself in
  a subprocess per model rather than patching the validated wrappers.
- **RVRT's CUDA build needs scratch space.** If `%TEMP%` is on a full drive, nvcc dies
  with `catastrophic error: ... No space left on device`, surfaced only as
  `ninja: build stopped: subcommand failed`. `run_qualitative.bat` sets
  `TORCH_EXTENSIONS_DIR` and `TMP`/`TEMP` onto the F: drive.
